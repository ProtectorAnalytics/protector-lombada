Os dois canais de comunicação da câmera

A câmera ALPHADIGI tem dois canais independentes, em telas diferentes do QLPR Config. Não confunda:

CanalTela QLPRDestinoFinalidade
Comunicação Conf. Comm → Comunicação lombada.appps.com.br:443 (HTTPS)
Protector		 Envia capturas e heartbeats, ambos no endpoint /placa. O backend distingue pelo conteúdo do payload (AlarmInfoPlate vs heartbeat).
Geren. remota Conf. Comm → Geren. remota portal.alphadigi.com.br:5080
IN IOT — cancelado		 Plataforma do fabricante. Contrato cancelado em 24/05/2026 — sem acesso ao portal. Recomendação: desabilitar esse canal em cada câmera no próximo acesso presencial.

Atenção: o indicador "Online / Offline" no rodapé do QLPR Config reflete a conexão com a Geren. remota (IN IOT), e não com o Protector. Uma câmera pode aparecer "Online" lá mas estar offline para nós (ou vice-versa). A fonte da verdade do Protector é o heartbeat e as capturas chegando no painel admin.

Causas mais comuns de "câmera offline":

  1. Câmera ainda apontando pro servidor IN IOT da ALPHADIGI 191.252.201.142:3000 (padrão de fábrica conforme manual oficial — não repassa mais ao Protector desde o cancelamento do contrato em 24/05/2026)
  2. DNS errado (não consegue resolver lombada.appps.com.br)
  3. Firewall do cliente bloqueando saída HTTPS na porta 443
  4. IP/Gateway mal configurados (sem rota pra internet)
  5. Link SSL desabilitado na câmera (Vercel só aceita HTTPS)

Diagnóstico rápido

Quando uma câmera aparecer com problema, comece pelo painel automatizado (botão "Diagnóstico" ao lado de cada câmera no admin, ou direto em /admin/diagnostico.html?camera_id=<uuid>). Ele mostra status em tempo real, últimas 24h de eventos do log conexao_log, IPs origem e veredicto de causa provável já correlacionado com os sintomas abaixo.

Se for investigar manualmente, use esta tabela pra correlacionar os sintomas:

Sintoma no ProtectorCausa provávelO que verificar
Sem heartbeat nunca registrado Câmera nunca conseguiu conectar — configuração incorreta Servidor/porta no canal "Comunicação" da câmera; serial cadastrado; DNS; firewall
Heartbeat parou há mais de 30 min Queda de internet, energia ou cabo Energia do painel, link do cliente, cabo de rede, status no QLPR Config (precisa estar no local)
Heartbeat OK, sem capturas há horas em horário de pico Sensor doppler desconectado, posicionamento incorreto, área de detecção fora Fiação sensor↔câmera (manual 03), área de detecção, linha de disparo no QLPR
Capturas chegando com placa em branco OCR não está lendo — iluminação, foco, ângulo Pixel da placa (130–200px), foco, zoom, suporte 3D nivelado, iluminação noturna
Velocidade 0 km/h em todas as capturas Sensor doppler sem comunicação com câmera Conexão A2/B2 do sensor (cabo roxo/laranja) e alimentação 12V do sensor
Rajada de capturas com timestamp antigo Câmera estava em retransmissão autônoma após queda — comportamento esperado Confirmar que o gap de heartbeat coincide; nenhuma ação necessária se estabilizou
"Online" no QLPR Config mas offline no Protector Geren. remota (IN IOT) OK, mas Comunicação (Protector) falhando São canais separados — checar Servidor Pri. = lombada.appps.com.br, Porta = 443, Link SSL habilitado e firewall HTTPS liberado

Troubleshooting passo a passo

Sequência a seguir quando uma câmera não está enviando dados para o Protector:

  1. 1. Confirme alimentação e rede física no local Painel LED acende? Cabo de rede conectado na câmera? LED da porta RJ45 piscando?
  2. 2. Verifique se a câmera tem internet Conecte um notebook na mesma rede e tente abrir https://lombada.appps.com.br/placa (esperado: resposta HTTP 405 "Método não permitido" — quer dizer que o endpoint responde). Se nem isso funcionar, o problema é da rede do cliente (DNS, firewall ou link).
  3. 3. Acesse o QLPR Config Notebook com IP fixo no range 192.168.0.x, navegador IE/Edge no IP da câmera. Senha PRO: admin. Senha LITE: admin123.
  4. 4. Confirme as configurações da seção "Comunicação" Servidor Pri. lombada.appps.com.br, Porta 443, Link SSL habilitado, ambas pastas (Nr.da Placa e Heartbeat) apontando para /placa, autenticação Anônimo. Veja tabelas acima. Se a câmera ainda estiver em 191.252.201.142:3000, este é o motivo do offline — reaponte agora.
  5. 5. Confirme DNS = 8.8.8.8 Em "Rede Local". DNS errado é a causa #1 de "não conecta nem aparece nada", agora que dependemos de resolução do domínio lombada.appps.com.br.
  6. 6. Confirme o número de série cadastrado no Protector Em "Manutenção do equipamento → Informação do Dispositivo", anote o "Nr série". No admin do Protector, verifique se a câmera com esse serial está cadastrada e ativa.
  7. 7. Solicite liberação de firewall ao cliente Saída TCP HTTPS (porta 443) para lombada.appps.com.br. Como agora usamos a porta padrão de HTTPS, costuma estar liberada — se não, o cliente precisa autorizar explicitamente.
  8. 8. Último recurso: reset físico Pressionar botão de reset por 30s com a câmera energizada. Cuidado: volta tudo pra fábrica, exige refazer toda a configuração (rede, comunicação, área de detecção, foco, zoom).
